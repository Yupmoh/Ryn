## Contract decisions

- Compatibility: additive APIs, shared native implementations, no breaking migration.
- ACK indicates processed decoded bytes, not GPU paint.
- Offsets cross JS safely as decimal strings.
- Host-authorized attachment identity and generation; output control and resize ownership independent.
- Bounded replay: refuse unavailable history rather than fabricate a reconstructed screen.
- Checkpoints optional and must preserve parser-state boundaries; no custom VT renderer.
- Sidecars host-defined, external instances never implicitly owned or killed.

### Frozen bridge shape

The new terminal bridge uses bounded pull reads, not pushed terminal events: create/attach/read/ack/write/detach/terminate/checkpoint/claimResize/resize/releaseResize/status. A caller starts reading only after attachment, removing subscribe-after-spawn races and avoiding ambient-window routing of background events. Long polls must complete below the bridge request deadline and dispose cleanly.

Opaque session/access/attachment/lease identifiers; generation and byte offsets are decimal strings. Output carries startOffset/endOffset plus base64 bytes. ACKs are cumulative and attachment-scoped. Host window identity is resolved internally. Initial configurable ceilings: 256 KiB in flight per attachment, 8 MiB retained bytes per session, 64 MiB aggregate, 8 MiB input and 64 queued inputs, 1 MiB checkpoint. These are conservative starting limits, not tuned performance claims.

Raw active streams release acknowledged history and continue indefinitely. Optional retained sessions may pause at retention limits until a valid checkpoint permits eviction; adapters must not accidentally enable retention on all raw terminals. Cross-platform baseline/acceptance remains outstanding.

## Document revocation acceptance gap

Current native callbacks do not expose a consistent trustworthy document replacement boundary. GTK NAVIGATED uses WEBKIT_LOAD_COMMITTED; WK uses URL KVO, which can miss same-URL reload and fire on same-document changes; WebView2 uses SourceChanged without IsNewDocument. LOAD-started is provisional and may precede cancellation; LOAD-finished is after new-page scripts can run.

Do not treat these callbacks as proof that old terminal attachment authority is revoked before new-document IPC. A renderer-supplied document registration ID is not an authority boundary: an old document retaining the launch token could register again. No such workaround was implemented. D1/G1 remain open pending a native trustworthy document-generation/commit integration and reload, same-document, blocked-navigation, and stale-IPC verification. Existing window-close attachment cleanup is not equivalent to navigation revocation.
